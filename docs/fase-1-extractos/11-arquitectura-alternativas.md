# 11 - Evaluación de Alternativas Arquitectónicas de Persistencia y Conexión

## 1. Contexto Arquitectónico y Neutralidad Tecnológica

El diseño del Hub Económico-Financiero para **Taquería El Criollo** rechaza la adopción precipitada o dogmática de un proveedor comercial en la nube como solución indiscutible antes de evaluar las demandas operativas y presupuestarias del negocio titular.

En observancia de los mandatos protocolares emanados del **Control de Calidad (Fase 0.5)**, la presente especificación evalúa de manera neutral, paramétrica y verificable las tres alternativas estratégicas de infraestructura relacional y conectores web capaces de albergar y dar vida a la **Capa Económica Común**:

* **Alternativa A (Backend BaaS Administrado):** Aplicación de página única (SPA en React 19) + Servidor relacional en nube **Supabase (PostgreSQL)** protegido mediante políticas de seguridad por fila (RLS), Edge Functions y almacenamiento en buckets oficiales.
* **Alternativa B (API Propia + PostgreSQL Dedicated):** SPA en React 19 + Servicio API REST/GraphQL propio desarrollado en Node.js (expandiendo o reformando `last_API/`) conectado contra una base de datos **PostgreSQL** alojada en un servidor dedicado o VPS independiente.
* **Alternativa C (API Propia + MySQL en Host Tradicional):** SPA en React 19 + API web o conectores seguros orquestados y ejecutándose directamente sobre el servidor **MySQL en cPanel / Bluehost** en activo (aprovechando la plataforma web tradicional corporativa de la empresa).

## 3. Recomendación Condicionada y Mandato Directivo

De la exhaustiva comparativa dimensional expuesta y del análisis de paridad funcional para **Taquería El Criollo**, la arquitectura de software enuncia el siguiente dictamen imparcial:
* **Decisión Propuesta como Recomendada a Mediano Plazo (`DECISIÓN PROPUESTA`):** La **Alternativa A (Supabase Protegido)** se erige como la opción más equilibrada para posibilitar una ejecución rápida y estructurada del MVP de Extractos en la Fase 2, gracias a sus conectores web relacionales eficientes, la seguridad delegada en RLS, el soporte integrado de ficheros temporales y su capacidad de escalar hacia horizontes multi-tenant sin sobrecargar al restaurante de gastos iniciales en DevOps o infraestructura dedicada.
* **Directriz Inmovible y Decisión Pendiente (`DECISIÓN HUMANA PENDIENTE`):** En estricta obediencia al marco normativo de control de calidad, **la arquitectura no selecciona de forma automática ni impone de manera unilateral y dogmática ninguna de las tres opciones**. El nombramiento oficial del motor servidor canónico (Supabase en nube, PostgreSQL dedicado en VPS o continuidad en cPanel MySQL) es una **decisión humana soberana e intransferible reservada a la deliberación directiva**, supeditada a que la gerencia evalúe de forma integral los equilibrios contractuales entre soberanía del dato, presupuesto operativo en tienda y facilidad administrativa para las cocinas y contabilidad del establecimiento.
